# Design — Google Calendar 3LO login

Seam: T001 implements the login routine, T002 calls it from the CLI. Nothing else is shared.

## 1. Contract

Contract lives in `rust/crates/worklog-core/src/collectors/gcal_auth.rs` (T001 creates it with exactly these public items; T002 imports them).

```rust
use std::io::Write;
use std::path::PathBuf;
use std::time::Duration;
use anyhow::Result;
use reqwest::blocking::Client;
use crate::browser::OpenOutcome;
use super::gcal::GcalAuth;

/// Google's consent endpoint. Tests swap in a fake via `AuthorizeOpts`.
pub const AUTH_URL: &str = "https://accounts.google.com/o/oauth2/v2/auth";
/// §5: stop waiting for the consent redirect after 300 s.
pub const CONSENT_TIMEOUT: Duration = Duration::from_secs(300);

pub struct AuthorizeOpts {
    pub auth_url: String,   // default AUTH_URL
    pub timeout: Duration,  // default CONSENT_TIMEOUT
}
impl Default for AuthorizeOpts { /* AUTH_URL, CONSENT_TIMEOUT */ }

/// Production entry: real browser opener, writes progress to stderr.
/// Returns the token file path on success.
pub fn authorize(auth: &GcalAuth, client: &Client) -> Result<PathBuf>;

/// Test seam. `open` receives the consent URL; `out` receives every
/// human-facing line (consent link, success, failure reason).
pub fn authorize_with<O, W>(
    auth: &GcalAuth,
    client: &Client,
    opts: &AuthorizeOpts,
    open: &mut O,
    out: &mut W,
) -> Result<PathBuf>
where
    O: FnMut(&str) -> Result<OpenOutcome>,
    W: Write;
```

Token exchange posts to `auth.oauth_base` (already the injectable token endpoint). Scope is `gcal::SCOPE`. Written file is `gcal::StoredToken`, serialised to `auth.token_path`.

## 2. Trust boundaries

| boundary | untrusted input | parse | failure |
|---|---|---|---|
| credentials file | JSON with `installed.{client_id,client_secret}` | serde struct in gcal_auth.rs | whole login fails, message names the path |
| loopback redirect | raw HTTP request line from any local process | parse `GET /?code=…&state=…` or `error=…` | reject request, keep nothing; state mismatch fails the login |
| token response | JSON from token endpoint | serde struct; `refresh_token` required | whole login fails, existing token untouched |

## 7. Decisions

- In the context of the redirect listener, facing "no new crates" and a single request, we chose `std::net::TcpListener` on `127.0.0.1:0` with a read timeout and rejected the daemon's axum stack, to keep the login synchronous like every collector, accepting hand-parsing one request line. Makes hard: nothing outside gcal_auth.rs.
- In the context of writing the token, facing FR-10 (failure leaves the old file intact), we chose write-to-temp-in-same-dir then rename and rejected writing in place. Makes hard: nothing.
