# CHK001 — Verdict control (human-verify, pre-approved: /flow:next --finish)

Observable: Owner switches Verdict on in Settings and sees "running", kills the helper and sees it come back, switches it off and sees the grey line on the day page.

## Setup (sandbox — real daemon and DB untouched)
- Binary: branch HEAD 60403e8 debug build (`cargo build -p worklog-cli`), copied to the job tmp dir.
- `WORKLOG_HOME=~/.claude/jobs/8ed228fc/tmp/wlhome` with a `sqlite3 .backup` copy of the real DB and a symlink to the real `verdict-model`. NOTE: secrets live in the shared OS keychain, so the sandbox daemon could reach the real Jira/Tempo; auto-send was off in the copy and no sync/send action was triggered.
- Daemon: `worklog daemon --tcp 127.0.0.1:9333`. Web: built app, `next start -p 3334` with `WORKLOG_DAEMON_URL=http://127.0.0.1:9333`.
- The Owner's own Verdict helper on :9324 (PID 54028, `worklog-dev verdict serve`) was paused with the user's OK ("whatever you think is best, im not using worklog right now") so the sandbox supervisor could own the fixed port.

## Steps and results
1. Verdict on → `GET /verdict/status` went `starting` → `running` (~30 s after daemon start). Day page shows no Verdict line (`CHK001-1-day-running.jpg`); Settings shows "● Running" (`CHK001-2-settings-running.jpg`). PASS
2. Killed the helper python (`kill -KILL 70242`) at 12:09:39 UTC. Status polled every 10 s:
   ```
   12:09:49 "state":"not_answering"
   12:09:59 "state":"starting"   (new helper pid 96672)
   12:10:09 "state":"running"    (96672 96701)
   ```
   Back to running within 30 s. PASS
3. Unticked "Run Verdict" in Settings → state line "● Off" (`CHK001-3-settings-off.jpg`); helper process gone (`pgrep` empty); status `{"state":"off","unchecked":1,...}`. Day page shows the grey line "Verdict is off · 1 event not checked · Turn on" (`CHK001-4-day-grey-line.jpg`). PASS

## Defects seen (fed to the design evaluator / fix pass)
- The "Run Verdict" checkbox's accessible name is "on", not "Run Verdict" (label not associated) — a11y.
- The checkbox sits far right of its label, detached from the state line (layout).
