## Contract for T101 — Topic count chosen by silhouette over one merge history
USAGE      `let (merges, n) = (stats_topics::merge_history(&centered), centered.len()); let k = stats_topics::choose_k(&centered, &merges); let labels = stats_topics::cut(&merges, n, k);`
CALLS      `stats_topics.rs:38` `cluster(vectors, k)` today runs UPGMA down to k and discards history; `:197` picks k = clamp(round(√(n/2)), MIN_TOPICS, MAX_TOPICS). Replace with: `pub struct Merges(pub Vec<(usize, usize, f32)>)` (pairs of cluster representatives merged, in order, with the merge distance) from ONE UPGMA run to a single cluster (reuse the existing loop and distance matrix; record each merge); `pub fn cut(m: &Merges, n: usize, k: usize) -> Vec<usize>` replays the first n−k merges with a union-find and returns labels numbered exactly like today's `cluster` (by lowest member) so `topics_of` is unchanged; keep `pub fn cluster(v, k)` as `cut(&merge_history(v), v.len(), k)` for existing callers/tests. `pub fn choose_k(centered: &[Vec<f32>], m: &Merges) -> usize`: precompute the cosine-distance matrix once (1 − dot, vectors are unit); for k in MIN_TOPICS..=min(MAX_TOPICS, n/5) take `cut`, skip if any topic has < MIN_TOPIC_BLOCKS members, compute mean silhouette (a = mean distance to own topic excluding self, b = min over other topics of mean distance; s = (b−a)/max(a,b); singletons s=0); keep the best, ties → smaller k; none qualifies (or n/5 < MIN_TOPICS) → old rule. Wire it at `:197–198`. Imports MIN_TOPIC_BLOCKS, MAX_TOPICS from topics_contract.
THE FIVE   (1) `cut` of the full history at k reproduces the old `cluster` labels on the existing test fixtures (same numbering). (2) Ties pick the smaller k. (3) A partition with a 2-block topic is never chosen. (4) n < 10 (n/5 < 2) falls back to the old rule — no panic, no empty range. (5) Deterministic: same input → same k and labels.
TESTS      stats_topics_test.rs: 13 well-separated synthetic blobs × 15 points (n=195; old rule gives 10) → `choose_k` = 13; 4 blobs + one 2-point blob → k = 4 (2-point topic rejected); `cut` vs old `cluster` equality on the existing fan fixtures; tie case; n=8 fallback. ## Contract for T102 — Cluster gravity and 3-D layout
USAGE      `topic_map::layout(&centered, &labels) -> Vec<[f32; 2]>`; `topic_map::layout3(&centered, &labels) -> Vec<[f32; 3]>`
CALLS      `topic_map.rs:150` `pub fn layout(v)` is hard-coded 2-D (`[f64;2]` in pca_init :78, normalise :129, vel/gains/rep/grad :159-161 :183, loops `0..2` at :93 :132 :191). Make the core generic: `fn embed<const D: usize>(v: &[Vec<f32>], labels: &[usize]) -> Vec<[f64; D]>` (pca_init takes the top D components with the same fixed start vectors, extended deterministically for c=2: `1 + ((k*7+3+c*5)%11)` already covers any c); `normalise<const D>` rescales to [0,1]^D by the largest span, centring the other axes (same rule as today). Gravity: from iteration EXAGGERATION_ITERS on, each iteration compute each topic's centroid of the current Y and add `GRAVITY * (y_i − c_topic)` to point i's gradient (same sign convention as the t-SNE gradient so it pulls toward the centroid). Start with the value that, in the prototype's units (gradient 4·Σ(p−q)·num·(yi−yj), lr 200), was 0.003, rescaled to this file's learning rate and gradient scale; then TUNE it with the split-fixture test below (prototype: 0.002–0.005 good, 0.01 too strong). `layout(v, labels)` = embed::<2> + normalise as f32; `layout3` = embed::<3>. `labels.len() != v.len()` → panic in debug (assert) — callers always pass matching lengths. n < MAP_MIN_POINTS → empty, as today.
THE FIVE   (1) Determinism: same input twice → identical output (2-D and 3-D). (2) No NaN/inf for duplicate vectors or a single topic. (3) Output in [0,1] per axis. (4) Gravity off-by-sign would scatter topics — the split test catches it. (5) Existing topic_map tests keep passing with labels supplied (use the true blob labels).
TESTS      topic_map_test.rs: split fixture — 6 topics, each made of TWO separate sub-blobs far apart in vector space (labels join the sub-blobs) → in both 2-D and 3-D, for every topic, single-link components at gap > 15% of the map span = 1 (no split), and nearest-dot-same-topic ≥ 0.95; natural fixture (labels = blobs) → topics still separate (between-centroid distance > 2× mean within-topic spread). 3-D output has non-degenerate z (std of z > 0.05). Bench (`#[ignore]`): n=2000 prints ms for layout and layout3.

## Contract for T105 — Star field (pure scene/camera module + canvas view)
USAGE      `const StarField = dynamic(() => import("./StarField"), { ssr: false }); <StarField report={report} />`
FILES      new: `web/components/stats/starfield.ts` (pure, no DOM), `web/components/stats/starfield.test.ts`, `web/components/stats/StarField.tsx` (`"use client"`, default export), `web/components/stats/StarField.test.tsx`, `web/app/stats/starfield.css` (import it from StarField.tsx the way other modules import their css — check how galaxy.css is loaded and mirror it).
CALLS      Pure module API (all numbers in world units, R = 100):
  - `buildScene(report: TopicsReport): Scene` — `stars[]` from `report.points`: `pos = [(sx−0.5)·2R, (sy−0.5)·2R, (sz−0.5)·2R]`, `r = 0.8 + 2.6·√(seconds / maxSeconds)`, `topic`, `firstTime` (block_id ∈ report.first_times), `oddball`, `label`, `day`, `seconds`, `ticket`, `novelty`; `topics[]`: `{id, name, centroid, spread (RMS distance of its stars to centroid), seconds}`; `dust[]`: 700 deterministic background points on a sphere of radius 6R from a seeded LCG (seed 1), brightness 0.2–0.6.
  - `initialCamera(scene): Camera` — `{pos:[0, 0.15R, −2.6R], yaw: 0, pitch: −0.05, fov: 60°}` looking at the origin (+z forward at yaw 0).
  - `forward(cam)`, `right(cam)` unit vectors; `stepCamera(cam, keys: ReadonlySet<string>, dt: number): Camera` — W/S along forward, A/D along right, E/Q world up/down, speed 0.6R/s, ×3 when `"Shift"` held; arrow keys rotate yaw/pitch at 1.4 rad/s; pitch clamped to ±1.45.
  - `look(cam, dxPx, dyPx): Camera` — 0.004 rad per pixel; `dolly(cam, wheelDeltaY): Camera` — moves along forward by −deltaY·0.05·R/100.
  - `orbit(cam, dt): Camera` — idle auto-orbit around the origin at 0.06 rad/s keeping distance and height, facing the origin.
  - `project(cam, p, w, h): {x, y, depth, scale} | null` — perspective with fov; null when behind the camera (depth ≤ 0.5).
  - `pick(projected: {i, x, y, rPx}[], mx, my, maxPx = 14): number | null` — nearest centre within max(maxPx, rPx); ties → nearer depth.
  - `flyTarget(cam, topic): Camera` — camera placed at `centroid − forward·max(2.2·spread, 0.35R)` looking at the centroid; `ease(a, b, t)` interpolates position and angles (cubic ease-out).
  View (StarField.tsx):
  - A focusable wrapper `<div className="sx-star" tabIndex={0} aria-describedby=hintId>` holding `<canvas role="img" aria-label="3-D star field: {n} blocks in {k} topics">`, a topic legend row (chips with colour + name; click → fly), the hint `"Click the field, then W A S D to fly · drag to look · Shift faster · R reset · Esc leave"`, a hover card (block label, topic name, day, hours via formatDuration, ticket if any) and a pinned info panel on click (adds "Newness N%").
  - Rendering per frame on a DPR-scaled canvas sized to the wrapper (ResizeObserver): fill background from the CSS token (getComputedStyle on the wrapper: `--bg` or the card token used in galaxy.css); dust (tiny, alpha by brightness, rotate with the camera only — infinitely far); topic nebulae (large radial gradient in topic colour at the projected centroid, radius `spread·1.8` projected, alpha 0.10 dark / 0.07 light); stars back-to-front: glow sprite (pre-rendered offscreen canvas per topic colour, radial gradient) at 4× r plus a solid core; alpha fades with depth (fog from 1.5R to 7R); first-time stars twinkle (sin(t·3 + i)) unless reduced motion; oddballs get a thin ring; topic labels (13px mono uppercase, topic colour mixed toward --fg, alpha by depth, hidden when behind camera) with hit boxes. In dark mode use `globalCompositeOperation = "lighter"` for glows; in light mode `"source-over"` with stronger cores. Resolve `oklch(...)`/`var(...)` colours to canvas-usable strings by setting them on a hidden element and reading `getComputedStyle(el).color` once per topic.
  - Loop: requestAnimationFrame only while (visible via IntersectionObserver) && (document visible) && (auto-orbit active OR keys held OR a fly animation running OR a drag in progress); otherwise draw on demand (resize, hover change, theme change).
  - Input: keydown/keyup on the wrapper only (preventDefault for handled keys so the page does not scroll); pointerdown + pointermove on the canvas for drag-look (setPointerCapture); wheel on the canvas with preventDefault (passive: false) only while focused; click → pick star (pin panel) or label hit (fly). Escape → close panel and `blur()`. Any input stops auto-orbit for good.
  - prefers-reduced-motion: no auto-orbit, no twinkle, fly is instant.
  - `canvas.getContext("2d")` null (tests, old browsers) → render the text "Star field needs canvas support." and no loop.
THE FIVE   (1) Key handlers only on the focused wrapper — the page never loses arrow/space scrolling elsewhere. (2) Loop stops when idle/off-screen (no 60 fps forever). (3) DPR scaling (crisp on retina) and resize. (4) Dark and light both readable. (5) No new dependencies; module is client-only and loaded lazily.
TESTS      starfield.test.ts: buildScene maps sx/sy/sz=0.5 to origin and 1 to +R; radii bounds; firstTime/oddball flags; topic centroid and spread exact on a 3-point fixture; dust deterministic (same first 3 points twice) and on the 6R sphere; stepCamera W moves +forward by speed·dt, Shift ×3, A/D perpendicular, pitch clamp; project of a point straight ahead lands at canvas centre, behind → null; pick nearest within radius and null outside; flyTarget looks at the centroid (forward·(centroid−pos) > 0.99·|centroid−pos|). StarField.test.tsx (happy-dom, no canvas context): renders the fallback text, the legend chips with topic names, the hint, aria-label with counts, wrapper tabIndex 0; keydown "w" on the wrapper calls preventDefault; keydown on document.body does not.

## Contract for T108 — Star field look: fit, constellations, label declutter, glow
USAGE      unchanged component; pure helpers in starfieldScene.ts / starfieldLabels.ts.
CALLS      Chrome screenshots (1440 px) show: all stars bunched in the middle third with lots of empty sky; topic names stacked on top of each other (e.g. "LIBRECHAT DEVELOPMENT" over "VÍS SJÚKRA INTEGRATION"); glows faint. Goal: an instantly beautiful, readable star map that is fun to fly. Changes:
  1. Fit (starfieldScene.ts): `initialCamera(scene, aspect = 16/9)` places the camera so the stars' bounding sphere (centre = mean of star positions, radius = max distance) fills 75% of the smaller of the vertical/horizontal FOV: distance = radius / tan(min(fovY, fovX)/2 · 0.75)… (state your exact formula in a comment and test it); looks at the bounding centre; slight downward pitch kept. Orbit and R-reset use this camera.
  2. Readable islands (buildScene): after positions are placed, for each topic with ≥ 2 stars scale offsets from its centroid so RMS spread = max(current spread, 0.22 × distance from this centroid to the nearest other topic centroid), capped so it never exceeds 0.45 × that distance. Pure, deterministic; topics with 1 star unchanged.
  3. Constellations: `constellation(points: Vec3[]): [number, number][]` — Euclidean minimum spanning tree (Prim, O(m²) per topic, m ≤ 2000 total) over a topic's stars; draw each edge as a 1 CSS-px line in the topic colour, alpha 0.28 dark / 0.18 light, multiplied by the fog of the nearer endpoint; edges of the hovered/pinned star's topic drawn at alpha 0.6.
  4. Labels (`starfieldLabels.ts`): `placeLabels(cands: {id, x, y, w, h, priority}[], pad = 6): {id, x, y}[]` — greedy in priority order (topic seconds desc), skip any candidate whose padded box overlaps an already placed box or leaves the canvas; label anchor = projected centroid shifted up by (projected spread radius + 12 px); a skipped topic's label still appears while one of its stars is hovered or pinned, or its chip is hovered.   5. Glow and depth: star core radius = max(1.6, r·scale) px capped at 16 px; glow sprite alpha 0.8 dark / 0.35 light at 5× core radius; nebula alpha 0.16 dark / 0.09 light with radius = max(projected spread·2.2, 28 px); dust gets a slow twinkle (unless reduced motion); fog from 0.8× to 3× the fit distance (relative to the fit, not fixed R).
  6. Hover feel: hovering a star brightens its topic (constellation 0.6, nebula ×1.6) and dims other topics' stars to 45% alpha; the hover card shows the topic name in the topic colour.
THE FIVE   (1) Deterministic (no Math.random). (2) No allocation-heavy work per frame beyond projections (MST computed once per scene). (3) Dark and light both readable. (4) 13px minimum text. (5) Reduced motion: no twinkle.
